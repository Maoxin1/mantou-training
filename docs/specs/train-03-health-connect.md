# TRAIN-03 · Health Connect 睡眠文件导入

2026-11-15，2.4.4 候选。基础是 2.4.3（`58184d3`），读取和本地文件通路已有独立实机探索（`10814a3`）。

| 验收项 | 行为 | 证据 |
| --- | --- | --- |
| 导入入口 | 在「记录」选择 mantou 睡眠导出 JSON。解析与预览均在本机，勾选后确认保存，可离线使用 | 浏览器 390 / 820 像素宽度通过。真实手机导出文件另在一次性本地浏览器验证 |
| 日期与来源 | 使用结束时区归档醒来日期，保留记录标识、写入应用、区间和来源版本。估计睡眠由完整阶段计算，缺失则显示未知 | 模块测试覆盖时区、跨午夜、阶段不完整与格式拒绝 |
| 复盘与备份 | 每日记录、周复盘、文字和完整 ZIP 备份支持；复盘按日期计算有导入睡眠的天数 | 浏览器验证文字备份恢复，模块验证完整 ZIP 恢复及 Markdown |
| 查重与更新 | 同来源和标识的摘要完全相同则跳过。改版、同日多段、重叠、缺结束时区或已删除日期均保留待核对 | 模块与浏览器验证。三星 ZIP 批量和手动入口同样检查已存 Health Connect 撞期 |
| 保存中断 | 预览不写入。确认时重新检查所选日期；任一选项不能保存时，整批保留原状态 | 模块验证批次原子性；使用现有事务与账号缓存版本检查 |
| 跨端保全 | 两个浏览器共用一个本地签名测试账号，经过实际同步 API 和隔离 PostgreSQL。旧版未同步补记可与新版睡眠收敛，平板更新后可离线查看 | `TRAINING_UPGRADE_BASE=58184d3` 的升级演练通过。从另一个签名账号读取时仍为空 |

使用独立的每日字段保存 Health Connect 摘要。摘要大小固定，原始阶段留在手机导出的 JSON。此方案兼容 2.4.3 对普通每日记录字段的保留方式，无需提升 journal 版本。2.4.3 客户端可保留摘要，更新到 2.4.4 才提供该字段的显示和导入。

两端同时确认不同的 Health Connect 记录会进入现有同步差异流程。两端分别离线保存三星和 Health Connect 后同步时，保留双方来源，同日界面及 Markdown 提示待核对，复盘只计一个有记录的日期。当前候选对同日多段和来源冲突暂只提示，具体选择、合并和覆盖规则留待后续确认。

测试夹具均为合成数据。可设置 `TRAINING_PRIVATE_SLEEP_SAMPLE` 进行本地真文件验证，不填写时仅执行合成用例。实际设备的系统文件选择器、正式账号、后台自动导出和后台写入稳定性留作独立验收。
