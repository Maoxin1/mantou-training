# mantou · 训练卡

[![Tests](https://github.com/Maoxin1/mantou-training/actions/workflows/test.yml/badge.svg)](https://github.com/Maoxin1/mantou-training/actions/workflows/test.yml)
[![MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

轻量、离线优先的个人训练 PWA。打开就能查看计划，需要时记录一个动作，依据预设规则调整训练目标，每周导出到 Obsidian。

原生 JavaScript，无前端框架。适配手机与平板，采用白灰界面和蓝色强调。

在线使用：[mantou · 训练卡](https://mantou-training-offline.vercel.app/)。

## 功能

- 单动作记录：实际组次、余力、动作状态和训练条件。
- 规则进阶：主动开启验证后，连续两次达标才推进；可撤销目标调整。
- 临时减量、动作暂停、当前阻力与下一档设置。
- 安装到桌面；首次联网准备完成后，可离线查看、记录和导出。
- Markdown 周报、完整 JSON 备份与恢复。
- 可选邮箱验证码登录与跨设备同步，离线修改在应用打开并联网后补传。
- 不同日期和独立字段合并；同字段采用实际修改时间较新的内容，时间相同或无效的真实分歧再由本人选择。
- 餐次照片离线保存、按账号同步；复盘可连同照片导出 ZIP。

## 快速开始：本机模式

需要 Node.js 22 或以上版本。

```sh
git clone https://github.com/Maoxin1/mantou-training.git
cd mantou-training
npm ci
npm run build
npm start
```

打开 <http://127.0.0.1:4173>。默认不配置登录服务，也不会连接作者的数据库。记录只保存在当前设备；可在设置中导出和恢复备份。

```sh
npm test
```

测试涵盖训练进阶、备份、离线外壳、账号隔离、并发合并及反复冲突回归。浏览器测试与线上检查的入口见[贡献说明](CONTRIBUTING.md)；自动测试不能替代实际设备与真实邮箱验收。

## 自部署

### 只需离线与本机记录

执行 `npm ci` 和 `npm run build`，将 `dist/` 部署到 HTTPS 静态托管服务。应用使用域名根路径，不支持直接放到任意子目录，也不能双击 HTML 文件运行。

Vercel 可直接导入 Fork，保留仓库根目录与 `vercel.json`，不设置环境变量即可使用本机模式。未配置邮箱同步时，`/api/sync` 返回 503。

### 需要邮箱和多设备同步

部署到自己的 Vercel 项目，配置自己的 Neon Managed Auth 与数据库。步骤见 [ACCOUNT-SYNC.md](ACCOUNT-SYNC.md)。

| 环境变量 | 用途 | 是否公开给浏览器 |
| --- | --- | --- |
| `AUTH_URL` | 自己的 Neon Auth HTTPS 地址；构建时生成前端配置，服务端用于校验认证 | 是，仅服务地址 |
| `DATABASE_URL` | 自己的 Postgres 连接字符串 | 否，只在服务端使用 |

不要把数据库密码放进 `AUTH_URL`，也不要提交真实 `.env`、验证码或训练备份。`dist/cloud-config.mjs`、`dist/auth-sdk.mjs` 与 `dist/meal-zip.mjs` 均由构建生成。

本地静态服务器不运行同步 API；本地验证完整云端链路需使用 Vercel 的开发环境或自己的部署。

## 安装与更新

- Android：Chrome／Edge 菜单 → 安装应用／添加到主屏幕。
- iPad：Safari → 分享 → 添加到主屏幕。
- 等待状态显示“可离线使用”，再断网测试。
- 更新：设置 → 检查应用更新 → 新版就绪后重新打开。也可打开同一站点的 [更新入口](https://mantou-training-offline.vercel.app/update.html)。无需清空浏览器数据。
- 查看此前记录时，先在「记录」顶部选择对应日期；跨过午夜后默认日期会变化。

## 数据边界

未登录记录保存在设备 localStorage；已配置并登录后，训练记录和计划同步到该部署的后端。不同站点域名的本机存储不互通。

手机和平板离线时各自保存，重新联网并打开应用后再汇合；不承诺关闭应用后的后台同步。共享设备退出账号仍会保留未加密的本机缓存。每周建议导出完整备份。

默认训练安排来自一个家庭弹力带与自重训练场景，需要按自己的能力、器械和恢复情况调整。工具执行预设规则，不根据训练数据预测体型，也不提供诊断。没有记录不会自动加码；组数和训练天数不会自动增加。

## 两周试行与每日记录（2.1）

首页可主动开始一段14天的全身训练试行，周二／周四各一次，保留原分化计划与历史。每次场次保存当时计划；新版本不覆盖已有训练目标。

- 「记录」统一按日期填写训练后、饮食与次日恢复；允许分次自动保存、补记、部分完成、同日多场次和左右侧分别记录。
- 次数空白保留为未知，0保留为实际0次。每行能注明动作版本、阻力、休息和动作质量，同组换版本用额外行与备注标明。
- 每日反馈区分食用成本估算与采购付款；三餐、咖啡、体重腰围均可选填。餐次照片的保存与同步见下一节，无自动热量识别。
- 每期复盘随时预览、复制或导出Markdown，包含原始事实、信息覆盖、缺失日期与调整历史。不自动增加训练量或按两周数据推断体型变化。
- 备份JSON包含新旧数据；旧JSON自动补充空日志结构，不虚构实际反馈。
- 日志按字段合并；独立字段保留，同字段采用实际修改时间较新的值，时间相同或无效的真实分歧等待选择。删除使用标记防止旧设备恢复已删记录。时间戳依赖设备时钟，请保持自动校时；详见[同步说明](ACCOUNT-SYNC.md)。

本仓库只含通用模板和虚构测试，个人记录保存在设备和本人账号。导出后可手动放入Obsidian或提供给助手分析；助手不会自动取得账号数据。

## 餐次照片（2.2）

在「记录 → 填写饮食与每日反馈」选择早餐、午餐、晚餐或加餐，再拍照或选照片。可补充实际吃掉的份量和一句说明；下午饥饿与全天精力建议晚上回顾，未到相应时段时留空。

- 原图在设备端重新编码为 JPEG，去除原始照片元数据，每张不超过180KB，每天最多12张。
- 照片先保存在按账号隔离的 IndexedDB。首次联网登录后可离线记录；联网或点「同步照片」后补传。另一设备需登录同一邮箱并打开对应日期。
- 未登录照片只存此设备。登录后可主动迁入，不能自动归入一个未经确认的邮箱。
- 云端照片保存在独立的私有数据库表，不进入文字同步的5MB载荷。API验证邮箱会话、账号标识，每个查询按JWT用户ID过滤。删除清空照片内容并保留小型删除标记，防止旧设备重传后复活。
- 两周复盘可导出含照片的ZIP。解压后，将复盘Markdown与photos文件夹一起放入Obsidian。离线或同步失败时会提示照片可能不完整。
- 设置中可备份所有照片与文字记录ZIP；从ZIP恢复入口仅恢复照片，文字JSON仍通过原入口恢复。清理设备存储前先备份未同步内容。
- 照片用于复盘，并不自动生成热量或营养达标结论。

自部署：在现有数据库运行 migrations/002-meal-photos.sql。照片API复用现有 DATABASE_URL 和 AUTH_URL，无需配置额外存储密钥。正式数据库迁移前请先在隔离分支验证。

测试：`npm test` 覆盖账号隔离、离线保存、删除期间上传、旧数据重传及原有训练同步。`npm run test:browser` 是仅绑定 127.0.0.1 的集成测试，默认使用内存存储与模拟登录，验证拍照、两台浏览器、离线刷新和 ZIP 导出，不使用真实用户照片。独立测试数据库模式见[贡献说明](CONTRIBUTING.md)。自动检查不代替手机／平板的实际相机权限验收。

### 三星睡眠文件导入（2.3.1）

记录 → 导入三星睡眠 ZIP → 选择醒来日期及同一晚片段 → 预览确认保存。只在本机解压睡眠与睡眠阶段 CSV，原始 ZIP 不上传。归档到当地醒来日期，每天保留一份本人确认的睡眠汇总，保留所选片段来源；共同合并标识的片段默认勾选，重叠片段会阻止保存，片段之间未记录间隔单独显示；再次保存可明确替换，重复导入相同记录不重复累计。完整阶段记录可计算设备估计实际睡眠；缺失或重叠阶段保持未知。睡眠区间和实际睡眠分别展示，手填感受独立保留。保存结果沿用账号同步、离线记录、JSON备份和阶段Markdown复盘。文件不超过250MB，所选睡眠CSV解压后合计不超过50MB。此功能不是手表自动同步。


### 暂停动作与历史睡眠核对（2.3.2）

首页「调整后续训练安排」可手动暂停动作并填写原因；暂停卡不显示训练目标或记录入口，恢复需本人再次确认。新建场次保留当时暂停状态，旧场次及实际次数不变。暂停原因和计划调整历史随账号同步、备份和复盘导出。旧版缺少分段来源标识的睡眠摘要显示重新导入核对提示；提示不表示该条数据一定错误。浏览器验证：`node tests/browser-paused.mjs`。
